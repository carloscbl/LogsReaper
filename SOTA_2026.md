# SOTA 2026 Notes

This design tracks stable, production-oriented techniques rather than experimental online classification.

## Interoperable Log Shape

OpenTelemetry Logs provide a practical model for timestamp, observed timestamp, severity, body, resource, attributes, trace id, and span id. LogsReaper mirrors that vocabulary in its IR so results can be mapped into broader observability pipelines.

Reference: https://opentelemetry.io/docs/specs/otel/logs/data-model/

## Template Mining

Drain-style parsing remains useful for unstructured logs because it treats high-cardinality tokens as variables while preserving stable message structure. LogsReaper v1 uses deterministic regex normalization; a later version can add Drain3-style online template mining for higher precision.

Reference: https://github.com/logpai/Drain3

## Columnar IR

Parquet and Arrow are the right default for repeated scans, comparisons, and ML feature generation. They compress repeated strings well and support efficient projection over only the columns needed for a query.

References:

- https://arrow.apache.org/docs/python/parquet.html
- https://parquet.apache.org/

## Local Analytics Engines

DataFusion and Polars are good future compare/query engines once run directories grow beyond simple in-memory aggregation. The MVP keeps compare logic in Python but writes a format those engines can read.

References:

- https://datafusion.apache.org/python/
- https://docs.pola.rs/user-guide/concepts/streaming/

## Rust Acceleration

Rust is a good fit for fast line splitting, tokenization, hashing, and optional Python bindings:

- `memchr` for fast byte scanning.
- `rayon` for parallelism.
- `regex-automata` for regex engines.
- `blake3` for stable fast fingerprints.
- PyO3/maturin for packaging as a Python extension.

References:

- https://docs.rs/memchr/
- https://docs.rs/rayon/
- https://docs.rs/regex-automata/
- https://docs.rs/blake3/
- https://pyo3.rs/
- https://www.maturin.rs/

## JSON Parsing

`serde_json` is the conservative Rust baseline. `simd-json` is a later optimization candidate if benchmark data shows JSON parsing dominates.

Reference: https://simdjson.org/

## LLMs

Recent log-parsing research uses LLMs for semantic grouping and explanation, but the v1 classifier is intentionally offline and deterministic. LLM-generated reports can be layered later over the Parquet IR without changing the core scan result.
